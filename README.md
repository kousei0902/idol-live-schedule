# 推しスケ

アイドル・アーティストのライブスケジュールをまとめて確認できる、スマホブラウザ向けの個人用アプリ。

## アプリ本体

`index.html` をブラウザで開くだけで動作します(サーバー不要)。データはブラウザの localStorage に保存されます。

- ライブの追加・編集・削除
- ステータス(参戦する/気になる/未定/終了)での絞り込み
- グループ名での絞り込み・検索
- 次のライブまでのカウントダウン表示

## 自動監視(新着ライブ情報の収集)

`watchlist.json` に登録したURLを、GitHub Actions が3時間ごとに自動でチェックし、新しいライブ情報(グループ名・日時・会場)を見つけたら GitHub Issue を作成して知らせる仕組みです(`.github/workflows/watchlist-check.yml` / `scripts/check_watchlist.py`)。GitHubのサーバー上で動くので、自分のPCを起動していなくても動きます。無料(Anthropic APIなどの課金なし)。

### 対応サイト(構造化抽出)

以下のサイトはページのHTML構造を解析して、イベントごとに「グループ名・日時・会場」を実際に抜き出します。

- **tiget.net** — カテゴリ一覧ページ(`/events?categories=...`)。通常のHTTP取得で解析
- **livepocket.jp** — カテゴリ検索ページ(`/event/search?l_cat=...`)。AWS WAFのJS認証チャレンジがあるため、Playwright(ヘッドレスブラウザ)経由で取得
- **eplus.jp** — ジャンル一覧ページ(`/sf/live/...`)。通常のHTTP取得で解析
- **ticketdive.com** — ジャンル絞り込み機能が無いため、トップページの「新着エントリー」欄(Next.jsのページ内埋め込みJSON `__NEXT_DATA__` から取得)。**アイドル以外のジャンルも混在します**

これら以外のURLを登録した場合は、ページ内容が変化したかどうかだけを検知する簡易モード(ハッシュ差分)にフォールバックします。

**ページネーション**: tiget・livepocket・eplusはページ送りに対応しており、1サイトあたり最大4ページ(`watchlist.json`の各エントリで`"max_pages"`を指定すれば変更可能)まで自動で辿ります。サイトへの負荷を抑えるため、ページ間に約1.5秒の間隔を空けています。TicketDiveは「新着エントリー」欄のみでページ送り自体が無いため1ページ固定です。

### 監視対象の追加方法

`watchlist.json` に以下の形式で追加してください。

```json
[
  {
    "group": "表示名",
    "url": "https://tiget.net/events?categories=29",
    "note": "任意メモ"
  }
]
```

- `group`: 表示用のラベル(構造化抽出の場合は各イベントの出演者名がグループ名として使われます。この`group`は主にログ・Issue上の見出し用です)
- `url`: 監視したいページのURL。対応サイトなら一覧・カテゴリページを推奨(トップページは無関係な新着枠が多く精度が落ちます)
- `note`: 任意。どんなページかのメモ

追加・編集したら commit & push すれば、次回のチェックから対象に含まれます。

### 仕組み

- `events.json`: 構造化抽出で見つけた各イベント(URLをキーに、グループ名・日時・会場・初検知日時)を保存(自動更新。手動編集不要)
- `state.json`: 対応サイト以外(ハッシュ差分モード)のURLについて、前回チェック時のハッシュ値・日時を保存
- GitHub Actions が3時間ごとに起動し、`watchlist.json` の各URLを取得
  - 対応サイトなら一覧からイベントを抽出し、`events.json` に無い(=新着の)ものだけを拾う
  - 新着イベントが見つかったら、1回のチェックでまとめて1件の GitHub Issue を作成(グループ名・日時・会場・リンクを箇条書きで記載)
  - 非対応サイトはページ内容のハッシュが変わったかどうかだけ判定し、変化があれば別途 Issue を作成
- GitHubのデフォルト設定では、Issueが作成されるとリポジトリオーナーにメール通知が届きます

### 手動でテスト実行する方法

GitHubの当該リポジトリページ → 「Actions」タブ → 「Watchlist Check」 → 「Run workflow」で、スケジュールを待たずにすぐ実行できます。

### 制限・注意

- 抽出ロジックは各サイトのHTML構造(CSSクラス名など)に依存しています。サイト側のデザイン変更で構造化抽出が壊れる可能性があります(その場合はエラーなく0件検知になりがちなので、たまに`events.json`の更新が止まっていないか確認してください)
- 会場・日時が空欄で取れるケースもあります(サイト側で未掲載の場合など)
- チェック間隔は `.github/workflows/watchlist-check.yml` の cron 設定で変更できます(GitHub Actions の実質的な最短間隔は5分ですが、頻繁すぎる実行は避けてください)
